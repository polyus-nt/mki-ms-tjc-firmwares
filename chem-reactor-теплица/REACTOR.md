# Реактор через дополнительный шлюз МС-ТЮК

Ветка `feat/chemical-reactor-integration` в **arduino-actuator, tjc-sketch,
tjc-commutator**. Изменения относятся только к теплице-химреактору.
ФабЛаб, novosib, Rust-приложение и прошивки stm32-u-reader не меняются.

## Arduino Due вместо Mega

Тот же `chemical_reactor.ino` теперь поддерживает **Arduino Due (Programming Port)**.
Номера GPIO, шлюз 17, формат команд и API сохранены. На Due используются TC0,
каналы 0/1/2, на Mega — облегчённые Timer1/3/4 CTC. Опросы периферии и приоритет
кадра шлюза сохранены. Пересобирать МС-ТЮК ради перехода Mega → Due не нужно.

Инструкция, отдельная таблица Due и команда сборки —
`arduino-actuator/chem-reactor-теплица/chemical-reactor/DUE.md`.
Пакет плат **Arduino SAM Boards**, не SAMD; библиотеки OneWire, DallasTemperature,
hd44780. USB-консоль — Programming USB, 115200. Входы Due и внешние подтяжки
должны быть 3,3 В. Не переносите 5-вольтовые сигналы Mega на Due.

## Подключение и прошивка

Компьютер → хаб **12** → SimpleBus → Arduino-шлюз **17** →
AustereMaster → Arduino Mega → программный SPI → три STM32.

Существующие узлы 13 (sensors), 14 (два вентилятора), 15 (кнопки),
16 (lmp8) остаются. Mega не заменяет Arduino вентиляторов.
Три двигателя, DS18B20, три LCD и три STM32 сохраняют свою распиновку.

| Пин нового шлюза | Сигнал | Mega | Направление |
| --- | --- | --- | --- |
| 1 | MISO | D40 | Шлюз → Mega |
| 2 | MOSI | D41 | Mega → шлюз |
| 3 | CLK | D42 | Mega формирует такты |
| 4 | CS | D43 | Mega выбирает шлюз |
| 5 | IRQ | D44 | Шлюз → Mega, LOW: есть данные |
| GND | Земля | GND | Общая земля |

D44 опрашивается обычным digitalRead, attachInterrupt не нужен.
Не соединять выходы питания независимых USB/БП. Питание и уровни — по штатной
схеме соответствующих плат. После программной перестановки моторов idx 0/1
STEP для idx 0/1/2 — D26/D29/D23, DIR D25/D28/D22; провода не меняются.

Из папки `tjc-sketch/chem-reactor-теплица`:

```powershell
py -3 scripts/build.py --target hub
py -3 scripts/build_gateways.py --gateway reactor
```

Если ARM GCC не в PATH — добавить `--toolchain-bin C:\tools\arm-gnu\bin`.
Выходы: `build/hub/sketch.bin`, `build/gateways/reactor/sketch.bin`.
Загрузка МС-ТЮК как usercode **0x08003800**, не поверх загрузчика.
Цель `all` теперь включает также reactor-шлюз. Тестовая `mega-link-test`
для рабочей системы НЕ подходит: она лишь шлёт A5 и не обрабатывает API.

Mega: открыть в Arduino IDE
`arduino-actuator/chem-reactor-теплица/chemical-reactor/firmware/chemical_reactor/chemical_reactor.ino`.
Выбрать Mega 2560, библиотеки OneWire, DallasTemperature, hd44780.
Austere и Hardware API включены локально, дополнительные библиотеки не нужны.
STM32 сохраняют существующий протокол v8, их перепрошивка для этой интеграции не нужна.
USB-консоль Mega остаётся на **115200**, номера моторов/STM в ней **1..3**;
в HTTP и аппаратном API — **0..2**. Это одни и те же устройства.

## Аппаратный протокол

Основа Hardware API v2 не меняется: 28 байт, CRC16, big-endian,
session_id/tx_id отражаются в ответе. Адрес назначения **17**.
Запросы проходят тот же арбитр READY → CLAIM → GRANT, без новой очереди или ретраев.
Шлюз прозрачно пересылает кадры. Проверка новых команд находится в
`firmware/common/ReactorProtocol.h`, копия — в Mega.

Таблица описывает ровно 8 байт data. Неуказанные байты должны быть нулевыми.
В скобках — число байт. Скорости: signed int32, **тысячные STEP/с или RPM**.

| Код | Команда | idx | Запрос data | Успешный ответ data |
| --- | --- | --- | --- | --- |
| 60 | Температура DS18B20 | 0 | Нули | centi°C signed(4), quality=3(1), age_ms(2), 0(1) |
| 61 | Установить STEP/с | 0..2 | milli-SPS signed(4) | Нули |
| 62 | Установить RPM | 0..2 | milli-RPM signed(4) | Нули |
| 63 | Остановить мотор | 0..2 | Нули | Нули |
| 64 | Удержание/EN | 0..2 | bool 0/1(1) | Нули |
| 65 | Микрошаг | 0..2 | делитель 4/8/16/32(1) | Нули |
| 66 | Скорости мотора | 0..2 | Нули | current milli-SPS signed(4), target milli-SPS signed(4) |
| 67 | Конфигурация мотора | 0..2 | Нули | enabled(1), running(1), ramping(1), делитель(1), full_steps/rev(2), 0(2) |
| 68 | Диагностика STEP | 0..2 | Нули | max_late_us(2), resyncs(4), 0(2) |
| 6A | Остановить все три | 0 | Нули | Нули |
| 6B | Прочитать таймер | 0..2 | Нули | remaining_seconds unsigned(4), duration_minutes unsigned(2), state(1), 0(1) |
| 6C | Запустить/сбросить таймер | 0..2 | минуты unsigned(4), 0..65535 | Нули |
| 70 | SET_U STM32 | 0..2 | целые мВ(4), 0..6000 | исходные мВ(4) |
| 71 | SET_I STM32 | 0..2 | целые мкА(4), 0..50000 | исходные мкА(4) |
| 72 | GET_U STM32 | 0..2 | Нули | измеренные мкВ со знаком(4) |
| 73 | GET_I STM32 | 0..2 | Нули | измеренные мкА(4) |
| 74 | GET_SETTED_U STM32 | 0..2 | Нули | исходные мВ(4) |
| 75 | GET_SETTED_I STM32 | 0..2 | Нули | исходные мкА(4) |

Числа кодов в таблице — шестнадцатеричные. Например, 60 RPM передаются как
60000 = 00 00 EA 60, остальные четыре байта data нулевые.

Таймеров три, по одному на логический канал. state: 0 idle, 1 running, 2 finished.
6C с минутами >0 сразу запускает/перезапускает отсчёт; 0 отменяет и очищает его.
Остаток округлён вверх до секунд, после завершения равен 0; исходная длительность
сохраняется до сброса/новой команды. Неверные idx/padding/диапазон не меняют таймер.
Отсчёт независимый, неблокирующий, переживает переполнение millis и потерю связи,
но не перезапуск Arduino. Это только индикация: окончание не меняет моторы или U/I.
На каждом LCD первая строка — Timer: mm:ss / --:-- / 00:00 DONE, без слова STM;
температура DS18B20 остаётся в API, строки SET/READ, U/I сохранены.
Таймер использует прежнюю карту lcdForStm: idx0/1/2 → LCD-слот2/1/3.

Для таймеров обновить хаб, шлюз17, Arduino реактора и FastAPI-сервис/консоль.
Новые команды проверяются ReactorProtocol.h и на хабе, и в шлюзе.
STM32 и остальные узлы теплицы обновлять не требуется.

Статусы прежние: INVALID_INDEX=1, INVALID_ARGUMENT=2, UNKNOWN_COMMAND=3,
SENSOR_UNAVAILABLE=5, BUSY=6, DEVICE_TIMEOUT=7, INTERNAL_ERROR=9 и остальные.
Микрошаг изменяется только при выключенном EN. Команда enable не меняет движущийся
мотор: сначала stop. RPM пересчитывается с текущим микрошагом на Mega; превышение
7000 STEP/с отклоняется без изменения уставки. OFF не добавлена.
Плохой/неполученный ответ STM32 даёт DEVICE_TIMEOUT, NOT_READY — SENSOR_UNAVAILABLE.
Ошибка ответа SET не доказывает, что действие не было выполнено; **не повторять
автоматически**.

## Поведение

Начальное состояние: все три двигателя остановлены, EN выключены.
После команды скорости мотор продолжает работу до новой команды или stop;
потеря компьютера/шлюза не останавливает его. Разгон сохранён. В текущем
варианте STEP генерируют лёгкие обработчики аппаратных таймеров Due или Mega.
Float-расчёты и разгон остаются в основном потоке; в ISR — целочисленное
обновление периода и STEP. Это не гарантия устойчивых 250 RPM на трёх моторах:
max_late_us/resyncs показывают опоздания IRQ, проверка на стенде обязательна.
Достаточно перепрошить плату реактора; шлюз и сервер не меняются.
ACK скорости подтверждает принятую уставку, не физическое движение и не окончание
разгона. Энкодеров нет. Состояние мотора на HTTP — три последовательных чтения,
не атомарный снимок. DS18B20 возвращает кеш, старше 3 с — ошибка, не фиктивный ноль.
STM32 читаются непосредственно; U/I не подменяются уставками.

Опросы температуры, STM32 и LCD продолжаются. Mega принимает/отдаёт не более
одного байта Austere за проход, без длинного ожидания полного пакета.
Austere остаётся 2 кГц; один кадр API из 28 байт занимает примерно 132 мс
без учёта накладных расходов и прерываний. Это не высокочастотный поток телеметрии.
Не запускать одновременно длинный USB SELFTEST и интенсивное внешнее управление.
Текст/бинарные кадры не смешиваются в USB Serial.

## Проверки

Из `arduino-actuator/chem-reactor-теплица/chemical-reactor`:

```powershell
py -3 scripts/test.py --cxx g++ --sketch-repo C:\projects\tjc-sketch --bridge-out C:\temp\reactor-chain.exe
```

Проверяется реальный C++ API и маршрутизация hub → gateway17 → Mega,
аргументы, периферия, ошибки STM32, сохранение состояния, байтовая очередь,
CRC, backpressure, двигатели и исходные тесты. Модели GPIO не заменяют стенд.

В `tjc-commutator/chem-reactor-теплица`:

```powershell
$env:CHEM_REACTOR_CHAIN = "C:\temp\reactor-chain.exe"
.venv\Scripts\python.exe -m unittest discover -s tests -v
Remove-Item Env:CHEM_REACTOR_CHAIN
```

Без переменной используется автономная wire-модель. С ней — production C++ API
хаба/шлюза/Mega с моделями аппаратуры; POSIX PTY дополнительно проверяет
HTTP → pySerial → SimpleBus → C++ → HTTP.
На стенде отдельно проверить уровни, направления линий, три STM32 на общей SPI,
ответ после включения, ручной stop и поведение без компьютера.
Моторы тестировать без опасной нагрузки; stop по Serial/HTTP не аварийная кнопка.
