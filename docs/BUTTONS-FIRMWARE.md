# Кнопочница: два концевика и две кнопки открытия

Рукописная прошивка `firmware/buttons/sketch.cpp`, платформа
`tjc-ms1-btn-a2/1.0`. Исходный класс `Button` скопирован в
`firmware/runtime/Button.hpp` из закреплённой ревизии lapki-compiler без изменений.
Вся конфигурация входов и полярности — `firmware/buttons/BoardConfig.h`.

| API idx | Пользовательский пин Button | Вывод STM32 |
| --- | --- | --- |
| 0 | 1 | PA1 |
| 1 | 2 | PA8 |

Кнопки открытия используют отдельные входы `Button(3)` (PA11) и `Button(4)`
(PA12), активны LOW. Концевики остаются на 1/2, API idx=0/1.
В фаблаб 3 открывает замок 0, 4 — замок 1; в химреакторе любая открывает
оба замка общего выхода. См. [полное описание](DOOR-CONTROL.md).

Адрес SimpleBus **15** (`0F`). UART/RS485 совпадает с общим runtime:
USART1 PB6/PB7, ReDe PA0, 9600 8N1. Обмен только через центральный хаб 12:
компьютер отправляет хабу запрос, `node=15`, `command=0x22`, `idx=0..1`.
Хаб пересылает его кнопочнице, она возвращает полный ответ хабу, хаб — компьютеру 99.
Arduino и Arduino-шлюз не участвуют в чтении этих концевиков.

## Подключение и семантика

Временная договорённость, **пока не проверенная на физическом монтаже**:

- Замкнутый на GND контакт: LOW, `get_door_state(idx) = true`, дверь закрыта.
- Разомкнутый контакт: HIGH, `false`, дверь открыта.

Подключайте сухой контакт между входом и общим GND. Не подавайте 5 В на GPIO
STM32. Внутренняя подтяжка вверх включена (`kEnableInternalPullup=true`), поэтому
открытый вход не плавает. Исходный `Button::pullup()` является заглушкой:
прошивка устанавливает PUPDR однократно после конструктора, а `scan()` его не меняет.
Если в конкретной аппаратной схеме уже есть подходящая внешняя подтяжка,
внутреннюю можно отключить в конфигурации. Полярность независимо меняется
для каждого входа через `kClosedWhenPressed[2]`.

Button сканируется постоянно, без `delay()`. Используется его подавление дребезга
50 мс и `isPressed()`, а не мгновенное поле `value`. В первые 50 мс после запуска
endpoint возвращает `SENSOR_UNAVAILABLE`: начальное состояние ещё не установлено.
Ответ содержит boolean в `data[0]` (0/1), остальные семь байтов — нули.
Это снимок текущего устойчивого состояния; возраста измерения в этом ответе нет.

Неверный idx получает `INVALID_INDEX`; ненулевой payload — `INVALID_ARGUMENT`;
запрос дверей на старый sensor node 13 — `INVALID_NODE`. CRC, session_id и tx_id
сохраняют общий формат API v2. Кнопочница не управляет магнитными замками напрямую.
Хаб читает `0x27` (node=15, idx=0, data=8 нулей): ответ — два монотонных
32-битных big-endian счётчика нажатий входов 3/4. Чтение их не очищает.
Считаются только новые устойчивые нажатия; удержание и зажатая при старте
кнопка не создают события. Это внутренний протокол, не HTTP/MCP API.

## Сборка и проверка

Из каталога tjc-sketch, Windows:

```powershell
py -3 scripts/build.py --target buttons
py -3 scripts/build.py --target hub
```

Linux/macOS: `make build-buttons build-hub`. ARM GCC должен быть в PATH либо
передан через `--toolchain-bin`. Результат: `build/buttons/sketch.bin` и
`build/hub/sketch.bin`. Перепрошейте кнопочницу и обновите хаб, чтобы он разрешал
новый маршрут дверей. Это usercode по адресу `0x08003800`, не образ загрузчика:
не стирайте загрузчик и не записывайте usercode по адресу `0x08000000`.
Скрипты сборки платы не прошивают.

Проверка через компьютер, указав рабочий порт адаптера:

```powershell
py -3 scripts/sensor_console.py COM15 --hex
```

```text
mstjuk> door 0
mstjuk> door 1
```

Замкните/разомкните каждый концевик и повторите чтение после 50 мс.
Убедитесь, что idx соответствует нужной двери и монтажная семантика верна.
`DEVICE_TIMEOUT` указывает на отсутствие полного ответа от кнопочницы, а не
на разомкнутый контакт. Не запускайте одновременно сервер и консоль на одном порту.

Native-проверка `tests/buttons_test.cpp` использует исходный Button с модельными
GPIO/часами: mapping, дребезг, независимость входов, стартовый таймер,
валидность запросов и wire-ответы. Это не заменяет физическую проверку подключений.
