# Быстрый SimpleBus: 115200 и арбитраж хабом

Актуально для ФабЛаб и химреактора. Формат SimpleBus и Hardware API v2
сохранён; изменены скорость общей шины и порядок начала внешних обменов.

## Обновление стенда

Остановите FastAPI, консоли и другие владельцы COM-порта. Соберите все прошивки
МС-ТЮК выбранной теплицы и обновите **все подключённые узлы**:
хаб, Arduino-шлюзы, кнопочницу и исполнительную лампочницу.
Смесь прошивок на 9600 и 115200 не работает.

ФабЛаб, из корня tjc-sketch:

```powershell
py -3 scripts/build.py --target all
```

Химреактор:

```powershell
cd "chem-reactor-теплица"
py -3 scripts/build.py --target all
```

При необходимости добавьте --toolchain-bin "C:\tools\arm-gnu\bin".
Прошивается usercode по 0x08003800; загрузчик не стирать.
Скорость и протокол самого прошивателя этим изменением не задаются.

Обновите tjc-commutator и запустите соответствующий FastAPI обычной командой.
Его COM-порт теперь автоматически открывается на **115200, 8N1**.
HTTP API и Rust-программы используют прежние методы и URL.
Штатная scripts/sensor_console.py и hub_test_console.py также работают на 115200;
hub-test — отдельная диагностическая прошивка, без согласования READY/CLAIM/GRANT.

**Arduino перепрошивать ради этого изменения не требуется.** AustereMaster между
Arduino и шлюзом не изменён. Arduino TEST USB Serial остаётся 9600, Newline.
Изменение полярности реле или распиновки — отдельная причина перепрошить Arduino.

## Устройство обмена

Хаб — арбитр общей полудуплексной шины.
Внутренний опрос кнопочницы планируется **раз в 2000 мс от начала прошлого опроса**.
Он не прерывает внешнюю команду: просроченный опрос выполняется на ближайшей
свободной границе. При отсутствии компьютера кнопки продолжают работать.

Предел внутреннего обмена — 250 мс. Успешный ответ завершает его немедленно.
Когда шина свободна, хаб предлагает окно компьютеру:

1. Хаб → PC: READY.
2. PC → хаб: CLAIM с идентификаторами этого окна и случайной солью процесса PC.
3. Хаб → PC: GRANT, подтверждающий именно CLAIM.
4. PC → хаб: **одна** команда, после которой хаб выполняет её полный пайплайн.
5. Хаб → PC: результат. Далее начинается новый обмен, без секунды тишины.

После READY и GRANT есть окно **100 мс**, отсчитываемое от конца их передачи.
Полный CLAIM/полная команда должны быть приняты в своём окне.
Молчание PC не блокирует автономную работу хаба. Окно — таймаут отсутствующего
участника, а не обязательная пауза при наличии ответа.

Истёкшее окно, чужой tx/session, повреждённый кадр и команда без GRANT
не исполняются. После простоя клиент немедленно сбрасывает старые входные
данные, без секундного ожидания. CLAIM можно повторить для нового READY, но
**аппаратная команда после GRANT отправляется только один раз**.
При потерянном ответе SET уже мог выполниться: автоматического повтора нет.

Это согласование транспорта, не авторизация: оно не заменяет физическую
защиту шины. Не подключайте дополнительные несогласованные инициаторы.
При задержке ОС/USB за пределы окна обмен может завершиться ошибкой;
стендовая проверка обязательна.

## Управляющие кадры v2

Обычный кадр: A5 5A, version=2, kind, tx_id, node, command, status, idx,
data[8], session_id[8], CRC16. Все многобайтовые числа Big Endian.

| Сообщение | kind | node | command | tx_id/session_id | data[8] |
| --- | --- | --- | --- | --- | --- |
| READY | 2 | 12 | F0 | Номер окна / эпоха H хаба | 00 64 00 00 00 00 00 00 |
| CLAIM | 1 | 12 | F1 | Как у READY | Случайная ненулевая соль S, u64 |
| GRANT | 2 | 12 | F2 | Номер окна / H XOR S | 00 64 00 00 00 00 00 00 |
| Команда | 1 | Узел API | Команда API | Как у GRANT | Аргументы API |
| Ответ | 2 | Как в запросе PC | Как в запросе PC | Как в запросе PC | Результат API |

У F0/F1/F2 status=0 и idx=0. READY/GRANT идут на SimpleBus-адрес PC 99 (63),
CLAIM/команда — на адрес хаба 12 (0C). F0/F1/F2 не маршрутизируются на Arduino.
Соль PC предотвращает смешивание ответов разных запусков сервера, в том числе
при перезапуске хаба; это не секретный токен и не административная авторизация.

## Скорость и оставшиеся расходы

Скорость задаётся BUS_BAUD=115200 в scripts/build_gateways.py обеих теплиц.
Сборка создаёт BusConfig.h в build/*/platform и патчит проверенные копии
SimpleBus.hpp/UART.hpp. Закреплённые upstream-исходники и их хеши не изменены.
Перед настройкой BRR UART отключается (включая UART, оставленный загрузчиком).
Делитель округляется к ближайшему целому и присваивается, а не объединяется побитовым OR.

Байт API по-прежнему передаётся пятью байтами SimpleBus.
28 байт API = 140 байт UART = около 12,15 мс на участок при 115200/8N1.
Искусственные 2-мс межпакетные паузы удалены.
Завершение физической передачи UART TC перед отпусканием ReDe сохранено.
Приём и таймеры обслуживаются между отдельными пакетами.
Кольцевой буфер SimpleBus — 64 полезных байта, переполнение обнаруживается.

Граница PC–Arduino содержит четыре участка SimpleBus и отдельный Austere.
Austere остаётся 2 кГц: 9 бит плюс CS-интервалы на байт; запрос/ответ по 28 байт
требуют примерно 0,26 с только этого транспорта. Поэтому полный API-вызов
не становится 24 мс, а полного снимка из 12 отдельных чтений за 24 мс нет.
--interval Rust-программы по-прежнему задаёт паузу после полного обхода датчиков.

## Проверки

```powershell
py -3 scripts/test_doors.py --cxx g++
py -3 -m unittest discover -s tests -p "*_test.py"
```

В tjc-commutator и его папке химреактора:
```powershell
py -3 -m unittest discover -s tests
```

На стенде: probe, все чтения, затем безопасные ручные управления и чтения
фактического состояния. Проверьте кнопки без сервера; отключите нижний узел,
убедитесь в конечной ошибке и доступности остальных узлов.
Измерьте время запросов, ошибки CRC/overflow и работу под длительным опросом.
Программные тесты и сборка не заменяют проверку реальной общей шины и USB-драйвера.
