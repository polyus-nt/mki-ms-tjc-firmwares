# Рукописные прошивки Arduino-шлюзов

Экспериментальная реализация аппаратного API на ветке `feat/hardware-api-gateways`.
Центральный хаб описан в [HUB-FIRMWARE.md](HUB-FIRMWARE.md). Старый GraphML не участвует в сборке.
Формат кадра v2 пока является проектом; запуск на стенде требует согласованного
перехода Arduino, шлюзов и хаба на этот формат.

## Состав

- `firmware/gateway/sketch.cpp` — одна единица трансляции с аппаратным runtime.
- `firmware/gateway/Gateway.h` — транспортный автомат без зависимостей от STM32.
- `firmware/common/HardwareProtocol.h` — копия общего C++11-кодека из
  `tjc-commutator/firmware/common`; при изменении контракта копии синхронизируются.
- `scripts/build_gateways.py` — проверка upstream SHA-256, исправление локальной
  сборочной копии runtime и создание трёх комплектов ELF/BIN/MAP.
- `tests/gateway_test.cpp` — native-проверки автомата и опубликованного кадра.

Сборки отличаются только `GATEWAY_NODE`: 13 для датчиков, 14 для первых четырёх
вентиляторов, 17 для оставшихся двух. На линии шлюз→Arduino индексы локальные:
14: `0..3`, 17: `0..1`. Глобальные `0..5` преобразует хаб, не шлюз.
Ответы SimpleBus адресуются хабу 12. Шлюз проверяет CRC, version, kind, статус
запроса и собственный node. Конкретные команды, индексы и типы датчиков проверяет
Arduino: шлюз не содержит старую карту оборудования и не управляет замками.

## Runtime и сборка ARM

Используется `kruzhok-team/lapki-compiler` на ревизии
`c0e235f364f21b1a7ba8dbb598ef0bc983511af6`, платформа
`compiler/platforms/tjc-ms1-ard-a1/1.0/tjc-ms1-ard-a1-1.0.json` и библиотека
`compiler/library/tjc-ms1-ard-a1/1.0/source/`.

Нужны Python 3 и `arm-none-eabi-g++`, `arm-none-eabi-objcopy`,
`arm-none-eabi-size`. Runtime этой ревизии уже входит в проект:

```sh
python3 scripts/build_gateways.py
```

Если ARM-инструменты не в PATH, добавьте `--toolchain-bin /path/to/toolchain/bin`.
`--prepare-only` проверяет и подготавливает runtime без компиляции.
Runtime уже включён в `firmware/runtime`; отдельный checkout не требуется.
На Windows: `py -3 scripts/build_gateways.py`, ARM `.exe` выбираются автоматически.
Скрипт не скачивает зависимости и не изменяет исходники runtime.

Результаты: `build/gateways/sensors/sketch.{elf,bin,map}` и
`build/gateways/actuator/sketch.{elf,bin,map}` и
`build/gateways/actuator-2/sketch.{elf,bin,map}`. Каталог build исключён из Git.

Только новый шлюз: `py -3 scripts/build.py --target gateway-actuator-2` или
`make build-gateway-actuator-2`; результат `build/gateways/actuator-2/sketch.bin`.

Сохраняются Cortex-M0+, Thumb, `STM32G030x6`, `nosys.specs`, `-Os`, startup,
`system.c` и linker script платформы. Добавлены C++11, отсутствие RTTI и
`-fno-strict-aliasing`; QHSM отсутствует, потому что прошивка не использует его.
Таблица векторов остаётся по `0x08003800`, как в загрузчике платформы. BIN —
только usercode, его нельзя писать по адресу начала Flash или поверх загрузчика.
Метод прошивки здесь не добавлен: сначала подтвердите ревизию платы и загрузчик.

Локальная сборочная копия upstream исправляется строго по проверенным хешам:

1. FIFO SimpleBus увеличено с 5 до 64 ячеек (63 полезных), full обнаруживается,
   overflow защёлкивается; доступ из ISR/main согласован короткими секциями с
   сохранением PRIMASK. При overflow непрочитанные байты отбрасываются.
2. Сдвиг UART-парсера выполняется побайтно вместо невыравненных uint16_t-доступов,
   недопустимых для Cortex-M0+.
3. В ArduinoAdapter исправлен инвертированный признак переполнения TX; ошибка
   остаётся защёлкнутой до чтения. Дополнительно контролируются счётчики
   `arduino_link_rx_overrun_count` / `arduino_link_tx_drop_count`.

RX/TX Austere upstream имеют по 32 байта. Полный запрос из 28 байтов ставится
в TX атомарно только при наличии места; частичный запрос не ставится.

## Обмен и восстановление

При старте шлюз дренирует вход до 250 мс тишины. Он принимает полный 28-байтовый
кадр, затем пересылает его Arduino без изменения реквизитов и payload. Только
один запрос ожидает ответа. Ответ принимается при совпадении
version/kind/session_id/tx_id/node/command/idx, корректном CRC и известном статусе. Ошибки
должны иметь нулевой payload. Опоздавшие/чужие ответы отбрасываются.

Предел транзакции — 1500 мс от приёма полного запроса шлюзом. При timeout или
overflow создаётся ответ DEVICE_TIMEOUT/TRANSPORT_OVERFLOW с исходными
реквизитами; Arduino-очереди очищаются. После отправки ошибки нужно 250 мс
тишины Arduino и входа шлюза, прежде чем принимать следующую команду.
Автоматического повтора изменяющих операций нет.

В одном буфере хранится отложенный BUSY для второго запроса, пришедшего во время
обмена; он передаётся только после полного основного ответа. Последующие
нарушающие очередь запросы отбрасываются без роста памяти. Нормальный хаб не
посылает второй запрос до завершения первого. SimpleBus не имеет source-поля;
хаб должен быть единственным инициатором обмена с этими шлюзами.

Ответ SimpleBus передаётся по одному пятибайтовому пакету, с паузой не менее
2 мс между концом предыдущего пакета и началом следующего. Основной цикл
обслуживает оба RX и таймеры во время пауз. Upstream sendPacket блокирует только
передачу одного пакета (~5.21 мс при 9600 бод), а не всей транзакции.

Молчание не доказывает отсутствие данных в произвольно остановленной Arduino;
v2 защищает от старых ответов сравнением session_id вместе с tx_id.
Смена сессии позволяет переиспользовать tx_id без накопительного лимита. Timeout меняющей команды означает
неизвестный исход, а не доказательство отсутствия воздействия.

## Проверки

Native-проверка с санитайзерами:

```sh
g++ -std=c++11 -Wall -Wextra -Werror -fsanitize=address,undefined -g \
  tests/gateway_test.cpp -o /tmp/tjc-gateway-test
/tmp/tjc-gateway-test
```

В окружении с ptrace LeakSanitizer недоступен: для этой проверки без выделения
памяти запуск выполнен с `ASAN_OPTIONS=detect_leaks=0`; AddressSanitizer и
UndefinedBehaviorSanitizer остаются включены.

Проверяются три node, неизменность опубликованного request/response, повреждённый
CRC, неполный запрос, неверный node/version/status, прозрачность специальных
байтов, все поля корреляции, applied PWM вместо запрошенного, timeout/поздний
ответ/восстановление, отложенный BUSY, overflow и переполнение millis.

Целевая сборка выполнена ARM GCC 14.3.1 с исходниками указанной ревизии: создано
три ELF/BIN, таблица векторов подтверждена по `0x08003800`; обработчики
USART1/EXTI4_15/SysTick присутствуют по одному. Линкер сохраняет предупреждения
nosys о недоступных POSIX syscalls и RWX-сегменте из исходного linker script.
Результаты native не означают проверку GPIO/IRQ или доставки на стенде.
Загрузка на устройство и стендовый обмен пока не выполнены.
