# Обычная лампочница ФабЛаб: замки и пылесос

Платформа **tjc-ms1-lmp-a3/1.0**, три выхода, не восьмилампочница.
Прошивка firmware/lmp/sketch.cpp, конфигурация firmware/lmp/BoardConfig.h.
SimpleBus-адрес 16, хаб 12. API и адреса не меняются, Arduino не участвует.

| Пин платы / LED | Устройство | HIGH | LOW | При старте |
| --- | --- | --- | --- | --- |
| 1 | Замок idx=0 | Разблокирован | Заблокирован | LOW |
| 2 | Замок idx=1 | Разблокирован | Заблокирован | LOW |
| 3 | Пылесос | Включён | Выключен | LOW |

Пылесос включается HIGH. Замки имеют другую семантику: HIGH открывает, LOW закрывает. Это не относится к реле питания на Arduino,
у которых остаётся active LOW. Не переносите полярность с одной платы на другую.
Выход замка — команда блокировки, не измеренное положение двери;
концевики по-прежнему читаются отдельно на кнопочнице.
На обычной лампочнице нет пользовательских выходов 4..8.

## Исходный LED и безопасный запуск

Используется LED.h именно lmp-a3 из закреплённого lapki-compiler,
а не LED центрального хаба и не LEDController lmp8.
LED.on(100) выставляет HIGH, LED.off() — LOW непосредственно в GPIO.
LEDController::update() здесь не нужен. Промежуточная яркость для реле не задаётся.

Оригиналы находятся в firmware/runtime-lmp, лицензии и источник —
[UPSTREAM.md](../firmware/runtime-lmp/UPSTREAM.md). Сборка ничего не скачивает.
В build/lmp/platform создаются проверенные копии с патчами:
LED constructor устанавливает latch до GPIO output-mode; startup off()
заменён уровнями BoardConfig. Глобальная инициализация GPIO из Connector.hpp убрана,
чтобы инициализацией выходов владели конструкторы LED.
UART получает общие IRQ/FIFO/unaligned-access исправления проекта.

Это устраняет программно создаваемые импульсы при запуске usercode,
но не гарантирует уровень GPIO до запуска прошивки, в загрузчике или без питания.
Сначала проверить без силовой нагрузки. Катушки/пылесос не подключать к GPIO
напрямую: нужны внешние драйверы, защита нагрузки и ручное разблокирование.

## Команды Hardware API v2

SimpleBus: CR + ASCII HEX адрес + байт + LF, 9600 8N1.
28-байтовый Hardware API кадр с CRC, session_id и tx_id не меняется.

| Метод | command | idx | data запроса | data ответа OK |
| --- | --- | --- | --- | --- |
| set_door_lock(idx, lock_state) | 0x42 | 0..1 | bool, затем 7 нулей | 8 нулей |
| get_door_lock(idx) | 0x43 | 0..1 | 8 нулей | bool, затем 7 нулей |
| Открыть на 2 с (внутренний) | 0x44 | 0..1 | 8 нулей | 8 нулей |
| get_vacuum() | 0x52 | фиксировано 0 | 8 нулей | bool, затем 7 нулей |
| set_vacuum(enabled) | 0x53 | фиксировано 0 | bool, затем 7 нулей | 8 нулей |

true для замка — блокировка (LOW), для пылесоса — включение (HIGH).
get возвращает состояние управляющего выхода, не обратную связь силового устройства.
Команды релейного вентилятора химреактора 0x50/0x51 не исполняются в ФабЛаб:
корректные запросы получают NOT_IMPLEMENTED, без изменения GPIO.

Неверный idx → INVALID_INDEX, неверный bool/reserved → INVALID_ARGUMENT.
Последний идентичный запрос с тем же session/tx возвращает кэшированный ответ
без повторного действия; изменённый запрос с тем же ключом — REQUEST_ID_CONFLICT.
На шине нет аутентификации отправителя; User/Admin — группировка верхнего API.

Кнопки 3/4 на кнопочнице открывают соответствующий замок на 2 с.
Таймер неблокирующий, выполняется здесь и возвращает LOW даже без компьютера.
Новое нажатие перезапускает его, удержание нет; явный set_door_lock отменяет таймер.
При потере связи вне импульса последнее заданное состояние сохраняется.
[Полный сценарий кнопок](DOOR-CONTROL.md).

## Сборка и обновление

Из корня tjc-sketch:

```powershell
py -3 scripts/build.py --target lmp
# Или make build-lmp
```

Новый результат **build/lmp/sketch.bin**, usercode по **0x08003800**,
загрузчик не стирать. Старый build/lmp8/sketch.bin от прошлых сборок
не является прошивкой ФабЛаб и использоваться не должен.
Устаревшие --target lmp8 и make build-lmp8 в корне — только alias новой lmp:
они также создают build/lmp/sketch.bin. В папке химреактора lmp8 остаётся настоящей
восьмилампочницей со своим build/lmp8/sketch.bin.

Для изменения типа исполнительной платы/полярности хаб и Arduino
обновлять не требуется: wire API прежний. ФабЛаб перепрошить обычную lmp,
химреактор — его lmp8 из соответствующей папки.

Тесты: py -3 scripts/test_doors.py --cxx g++, затем
py -3 -m unittest discover -s tests -p "*_test.py".
tests/lmp_test.cpp проверяет API, tests/lmp_outputs_test.cpp — физическую
полярность замков/пылесоса и таймеры; lmp_build_test.py — платформу и startup-патчи.
Проверка сборки не заменяет измерение уровней и времени на реальном стенде.
