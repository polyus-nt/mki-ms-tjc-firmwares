# Восьмилампочница фаблаб-теплицы: магнитные замки

Рукописная прошивка `firmware/lmp8/sketch.cpp` для `tjc-ms1-lmp8-a1/1.0`.
Адрес SimpleBus **16**, хаб **12**. Arduino не участвует.

**Эта прошивка — для фаблаб-теплицы.** Активны два независимых выхода
магнитных замков на пинах 1 и 2 и пылесос на пине 3.
Это последнее уточнение заменяет прежнее решение об общем выходе замков.
Релейный вентилятор относится к теплице-химреактору:
его исполнение явно закомментировано (`#if 0`) в `Lmp8Api.h`.
Матрица и неблокирующая пауза 250 мс сохранены как неактивная заготовка;
прошивка фаблаб не включает реле ни по одной команде.

## Выходы и полярность

| Пин компонента LED | STM32 | Назначение |
| --- | --- | --- |
| 1 | PA9 | Магнитный замок idx=0 |
| 2 | PC6 | Магнитный замок idx=1 |
| 3 | PA11 | Пылесос |
| 4 | PA10 | Не используется, HIGH |
| 5 | PA5 | Не используется, HIGH |
| 6 | PA6 | Не используется, HIGH |
| 7 | PA7 | Не используется, HIGH |
| 8 | PB0 | Не используется, LOW |

Распиновка взята из исходного `LEDController.hpp` платформы lmp8, а не хаба.
Используется компонент **LED**, который обновляет кэш `LEDController`.
`LEDController::update()` применяется сразу после изменения выходов.
Это push-pull выходы: **LED.on(100) = HIGH**, **LED.off() = LOW**.
**Замки:** HIGH разблокирует, LOW блокирует, каждый замок независимо.
**Пылесос:** HIGH включает, LOW выключает — обратная полярность относительно замков.
`lock_state=true` означает команду
блокировки выхода, а не измеренное положение двери. Концевики читаются отдельно
на кнопочнице. Публичные методы замков снова индексированы:
`set_door_lock(idx, lock_state)`, `get_door_lock(idx)`, idx=0..1.
Пылесос один: `set_vacuum(enabled)` и `get_vacuum()` без публичного индекса.

Все настройки — `BoardConfig.h`. При запуске **пины 1/2 LOW**, **пин 3 LOW**:
оба замка заблокированы, пылесос выключен. Неиспользуемые 4..7 HIGH, 8 LOW.
Build-патч сначала выставляет регистр выходного уровня, затем включает режим
GPIO output; штатный upstream init с кратковременным LOW не вызывается.
Это предотвращает намеренный импульс разблокировки при инициализации прошивки,
но не заменяет внешние подтяжки/аппаратную защиту при reset, загрузчике или обесточивании MCU.
Полярность `kLockActiveLow=true`, `kVacuumActiveLow=false` учитывается и в старте,
и при командах. `startupHigh()` задаёт стартовый уровень индивидуально для пинов.

**Проверять уровни без силовой нагрузки.** Релейные катушки и магнитные замки
нельзя подключать непосредственно к GPIO: нужны согласованные внешние драйверы
и защита индуктивной нагрузки. Сборка не прошивает устройство.

## Неактивная заготовка химреактора: матрица уровней

Следующая таблица **не исполняется в фаблаб-прошивке**.
Нумерация реле 2..7 — только прежняя заготовка другой теплицы; она не является
назначением пинов фаблаб. Пины 2/3 фаблаб заняты замком/пылесосом; массив LED реле,
его output-метод и выполнение матрицы исключены из сборки через `#if 0`.

| Уровень | Включённые реле (LOW) |
| --- | --- |
| 0 | нет |
| 1 | r1, r5, r6 |
| 2 | r1, r2, r5, r6 |
| 3 | r1, r2, r3, r5, r6 |
| 4 | r1, r2, r3, r4, r5, r6 |
| 5 | r1, r6 |
| 6 | r1, r5 |
| 7 | r1, r2, r6 |
| 8 | r1, r2, r3, r6 |
| 9 | r1, r2, r3, r4, r6 |
| 10 | r1 |

Сохранённый, но отключённый алгоритм химреактора: выключить все шесть реле → выждать
**не менее 250 мс** → применить всю матрицу → ответить OK. Включая уровень 0
и новую команду с тем же уровнем. Во время паузы UART продолжает работать;
`delay()` не используется. Другой запрос получает BUSY, не отменяя переключение.
Повтор идентичного активного запроса не перезапускает таймер. Последняя успешно
исполненная команда и ответ кэшируются по session_id/tx_id: её повтор не переключает
реле заново; изменённый запрос с тем же ключом даёт REQUEST_ID_CONFLICT.
Это кэш **одного последнего** ответа, а не вечное хранилище всех запросов.
При потере связи явно заданные состояния замков и пылесоса удерживаются.
Исключение — открытие кнопкой: локальный таймер lmp8 блокирует замок через 5 с,
даже если связь с хабом пропала. Новое нажатие перезапускает таймер; удержание нет.
Явный `set_door_lock` отменяет таймер данного замка. Подробнее:
[кнопки открытия и автономный таймер](DOOR-CONTROL.md).
Температурных/аварийных правил управления здесь нет.

В закреплённом runtime PLL: внешний HSE **8 МГц**, M=1, N=16, R=2,
SYSCLK=64 МГц, HPRE=/4 даёт HCLK=16 МГц. SysTick CLKSOURCE=HCLK,
reload=16000 (`HCLK /4 /1000` в system.c), значит `millis()` — 1 мс.
250 тиков соответствуют 250 мс при штатном источнике 8 МГц; другое аппаратное
тактирование требует пересмотра. Реальный интервал измерить при стендовой проверке.

## Команды Hardware API v2

Внешний SimpleBus остаётся `CR + адрес ASCII HEX + байт + LF`, 9600 8N1.
Запрос приходит на адрес 16, ответ отправляется на адрес хаба 12.
Полный API-кадр 28 байт с CRC, session_id и tx_id не изменён.

| Публичный метод | command | Внутренний wire idx | data запроса | data ответа OK |
| --- | --- | --- | --- | --- |
| set_door_lock(idx, lock_state) | 0x42 | 0..1 | bool 0/1, затем 7 нулей | 8 нулей |
| get_door_lock(idx) | 0x43 | 0..1 | 8 нулей | bool 0/1, затем 7 нулей |
| внутреннее открытие на 5 с | 0x44 | 0..1 | 8 нулей | 8 нулей |
| get_vacuum() | 0x52 | фиксировано 0 | 8 нулей | bool 0/1, затем 7 нулей |
| set_vacuum(enabled) | 0x53 | фиксировано 0 | bool 0/1, затем 7 нулей | 8 нулей |

Резервные команды химреактора `get_relay_level` (0x50) и `set_relay_level`
(0x51) известны wire-валидатору, но **не предоставляют работающий API фаблаб**.
Любой корректный такой запрос получает **NOT_IMPLEMENTED (4)** с восемью
нулевыми байтами data. GET не сообщает вымышленный уровень; SET не включает реле
и не выдаёт ложный OK. Неверные аргументы по-прежнему отвергаются валидатором.

Для пылесоса сервер сам выставляет **wire idx=0**: это внутреннее поле неизменённого
28-байтового протокола, а не пользовательский параметр. Прошивка и валидатор
по-прежнему отклоняют другое значение idx для пылесоса. Замки имеют idx=0..1.
У остальных индексированных устройств
(датчиков, концевиков, вентиляторов) индекс в публичном API сохраняется.

`get_door_lock` — состояние выхода, обратного датчика срабатывания замка нет.
`get_vacuum` — состояние управляющего выхода; отдельного датчика работы пылесоса нет.
Неверный idx → INVALID_INDEX; неверный bool/уровень/ненулевой reserved →
INVALID_ARGUMENT; неверный node → INVALID_NODE. Роли и административные ограничения
реализуются на сервере: SimpleBus endpoint сам не аутентифицирует отправителя.

## Сборка

```powershell
git pull
py -3 scripts/build.py --target lmp8
# Или make build-lmp8, если установлен make.
```

Результат `build/lmp8/sketch.bin`, usercode по **0x08003800**, без стирания
загрузчика. Хаб также пересобрать и обновить: старый валидатор не знает node16.
Локальные неизменённые `LED.h`, `LEDController.hpp`, `const.h`, `UART.hpp`, `system.c` находятся в
`firmware/runtime-lmp8`; внешние скачивания не нужны.

Native тест: `g++ -std=c++11 -Wall -Wextra -Werror tests/lmp8_test.cpp -o lmp8-test`,
затем запуск `lmp8-test`. Python: `python3 -m unittest discover -s tests -p '*_test.py'`.
