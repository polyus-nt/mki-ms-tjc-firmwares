# ADR-0002: Использовать сообщения фиксированного формата

## Status

Accepted

## Context

Обмен проходит через автоматы из `tjc-sketch`, для которых протокол с динамической длиной, экранированием и вычислением CRC создаёт несоразмерную сложность. В текущем обмене значение `3` одновременно используется как подтверждение и воспринимается как специальный байт, поэтому совпавший байт сжатого RPM заменяется на `255` и измерение искажается.

## Decision

Каждая команда определяет фиксированное количество и порядок следующих байтов. Получатель трактует байты данных по позиции, независимо от их значения. `OK` используется только как подтверждение после всех ожидаемых полей и никогда как разделитель внутри полезной нагрузки. Неполный обмен прерывается существующим тайм-аутом автомата.

RPM каждого из четырёх вентиляторов передаётся непосредственно как беззнаковое 16-битное целое, старшим байтом вперёд. Значения RPM не нормализуются к общему максимуму и не заменяются при совпадении с кодом `OK`.

В протокол не добавляются динамическая длина, экранирование и CRC. При изменении состава полей вводится новая команда с собственным фиксированным форматом, а не меняется смысл существующей команды.

Каноническое описание кодов команд, порядка полей и тестовых векторов хранится в `tjc-sketch/docs/protocol.md`. Arduino-прошивки, автоматы GraphML и Rust-декодер должны проверяться относительно одних и тех же примеров из этой спецификации.

Показания двух датчиков температуры сопровождаются одним байтом битовых признаков валидности и свежести. Повторно переданное последнее корректное значение отличается от нового успешного измерения соответствующим признаком свежести.

Внутренний выход PID не входит в обязательную телеметрию. Для наблюдения за фактическим воздействием передаются применённые PWM четырёх вентиляторов и соответствующие RPM. Если точное значение внутренней потребности в охлаждении станет необходимо для диагностики, оно добавляется отдельным полем нового фиксированного формата, а не восстанавливается как достоверное состояние по RPM.

## Consequences

Автоматы TJC остаются последовательностями простых состояний, а RPM вентиляторов с разными максимальными оборотами передаётся без потери точности. У каждого формата должен быть однозначно документирован порядок и размер полей.

Протокол обнаруживает отсутствие ожидаемого байта по тайм-ауту, но не гарантирует обнаружение подмены одного допустимого значения другим. Изменения формата требуют согласованного обновления спецификации, тестовых векторов, отправителя, автоматов TJC и получателя.
