# ADR-0003: Ограничить полномочия агента предвалидированными политиками

## Status

Accepted

## Context

Агент вызывается значительно реже локального контура, зависит от компьютера и внешнего API и может не ответить вовремя. При этом поведение системы при открытой двери должно применяться немедленно и оставаться определённым без агента. Целевая температура выражает требование оператора, а не способ оптимизации охлаждения.

Полное исключение агента из обработки открытой двери не позволило бы ему адаптировать высокоуровневую стратегию. Прямые команды произвольной мощности сделали бы безопасность зависимой от ответа модели.

## Decision

Агент может выбирать только одну из заранее реализованных и проверенных политик открытой двери:

- `FANS_OFF` — выключить обычное охлаждение и заморозить интегратор;
- `LIMITED` — ограничить обычное охлаждение настроенным безопасным уровнем;
- `CONTINUE` — продолжить регулирование, исключив этот период из оценки и настройки PID.

По умолчанию действует `FANS_OFF`. Arduino Uno применяет выбранную политику локально сразу после получения состояния двери. Последняя подтверждённая политика сохраняется при недоступности агента. Аварийная политика имеет приоритет над любой политикой двери.

Агент не может менять целевую температуру. Её задаёт оператор, а локальный контур применяет только после проверки допустимого диапазона.

Агент может предлагать относительные веса распределения нагрузки между вентиляторами. Локальный контур нормализует веса, исключает вентиляторы с подтверждённым отказом и не превышает разрешённый PWM.

Агент и оператор могут вызвать `probe_fan` для вентилятора с подтверждённым отказом. Локальный контур выполняет ограниченную проверку запуска и возвращает вентилятор в распределение только после успешного подтверждения RPM. Между попытками действует cooldown, а во время перегрева проверка запрещена.

Агент и оператор могут вызвать `clear_emergency`, после чего Arduino немедленно снимает аварийный режим. Команда не отключает safety-условие: оно заново проверяется на каждом локальном такте и повторно включает аварийный режим, пока сохраняется аварийное превышение температуры или другое аварийное условие.

## Consequences

Открытие двери имеет детерминированное поведение даже без компьютера и API, но агент сохраняет ограниченную возможность выбирать стратегию. Для изменения набора политик потребуется изменение и повторная проверка обычного кода, а не только промпта.

Интерфейс агента должен принимать перечислимое значение политики вместо произвольной команды мощности. Телеметрия должна отмечать открытую дверь, активную политику и аварийное переопределение. Запрос проверки вентилятора не является утверждением о его исправности, а снятие аварийного режима не подавляет повторное срабатывание локальной защиты.
