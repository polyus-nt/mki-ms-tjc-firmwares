# ADR-0005: Использовать DeepSeek Harness как агентный runtime

## Status

Accepted

## Context

Медленному агентному контуру нужны сессии, сборка запросов модели, цикл вызова инструментов, журналирование и ограничения выполнения. Самостоятельная реализация этого цикла в Rust дублировала бы возможности специализированного runtime. Официальный DeepSeek Harness предоставляет агентный цикл и MCP-клиент, но находится в developer preview и может получать несовместимые изменения.

Стандартный профиль Harness рассчитан в том числе на работу с кодом и может предоставлять shell, файловые и другие широкие инструменты, которые не нужны и опасны для агента управления охлаждением.

## Decision

DeepSeek Harness запускается как отдельный агентный runtime из самостоятельного репозитория `tjc-deepseek-harness` и подключается к локальному MCP-серверу `tjc-commutator`. Используется закреплённая точная версия Harness. В `tjc-commutator` остаётся только MCP-сервер и серверная проверка полномочий; зависимости, prompts, расписание и запуск Harness в него не входят.

Для прототипа Harness запускается отдельным командным скриптом и не устанавливается, не обновляется и не запускается самим Rust-приложением. Проверка установки выполняется отдельно на целевой машине.

Плановый агентный анализ запускается раз в пять минут в штатном режиме и раз в две минуты при активной кандидатной конфигурации, открытой двери, деградации или аварии. События сохраняются до обработки агентом; частота агентного цикла не используется как гарантия времени реакции safety-контура.

Для системы создаётся минимальный профиль Harness. Агент видит только явно разрешённые инструменты чтения состояния и истории, изменения ограниченных настроек, выбора политики двери, отката и уведомления оператора. Shell, редактирование файлов и прочие инструменты общего назначения в этот профиль не входят.

MCP-сервер принимает соединения только через loopback-интерфейс и требует сгенерированный токен, который передаётся профилю Harness через переменную окружения.

Полномочия включаются поэтапно: read-only, затем dry run и только после прохождения симуляционных сценариев — ограниченное автоматическое применение настроек. Целевая температура и safety-пределы остаются недоступны агенту.

## Consequences

Команда не реализует собственный агентный цикл и использует готовые сессии и трассировку Harness. Rust-приложение остаётся единственным владельцем оборудования, телеметрии и серверной валидации команд.

Поставка включает самостоятельный репозиторий с командными скриптами и конфигурацией Harness; Node.js-зависимости устанавливаются только на целевой машине. Репозитории Rust-приложения и агента можно версионировать и развёртывать независимо. Версию Harness требуется обновлять сознательно с повторным аудитом итогового набора tools и прогоном агентных тестов. Недоступность Harness или модели не влияет на локальный контур Arduino.
