# ADR-0001: Последовательные пайплайны под управлением хаба

## Status

Accepted

## Context

Компьютер и платы МС-ТЮК используют общую полудуплексную шину.
Кнопки открытия дверей должны работать без компьютера: хаб самостоятельно
получает события кнопочницы и управляет замками. Одной сериализации запросов
сервера недостаточно для согласования начала передачи с внутренним опросом хаба.

В текущей реализации сервер перед каждым запросом ожидает секунду тишины,
а хаб оставляет промежутки между фоновыми опросами. Эта договорённость
добавляет задержку и при полностью исправной аппаратуре.

Альтернативы: оставить определение свободного окна по тишине либо убрать
автономный опрос и возложить его на компьютер. Первая сохраняет задержки,
вторая лишает кнопки автономности.

## Decision

Центральная плата является арбитром аппаратного обмена. Внутренний пайплайн
опроса и пайплайн обработки команды компьютера выполняются последовательно,
а не параллельно. Текущий пайплайн завершается успешным ответом либо ошибкой,
в том числе по конечному таймауту.

Внутренний опрос планируется раз в две секунды. Наступление срока опроса
не прерывает выполняющуюся команду; просроченный внутренний опрос выполняется
на ближайшей свободной границе перед следующей внешней командой.

После внутреннего опроса хаб разрешает фазу внешних команд. Компьютер начинает
передачу только после явного сообщения готовности от хаба. Завершение успешного
обмена не требует обязательной защитной паузы или ожидания полного таймаута.

## Consequences

Кнопки сохраняют автономность. Право начать передачу согласуется явно,
поэтому секундное ожидание тишины перед каждым штатным запросом подлежит замене.
Смена фаз требует согласованных изменений хаба и компьютерного транспорта.

При длительном обмене фактический интервал внутренних опросов может превышать
две секунды. Сроки ожидания должны учитывать время физической передачи.
Увеличение скорости UART и уплотнение формата сообщения — отдельные изменения;
эта запись не задаёт новый baud rate.

Перед реализацией требуется определить кодирование сообщения готовности,
завершение внешней фазы при пустой очереди или отсутствии компьютера,
а также обработку запоздалых ответов после таймаута.

Это решение описывает целевую архитектуру; существующие прошивки и сервер
пока используют предшествующую договорённость по тишине на шине.
